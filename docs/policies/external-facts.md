# External facts

Verify claims that are unstable, version-sensitive, provider-owned, or
otherwise likely to have changed before presenting them as facts. Prefer the
authoritative upstream documentation, release record, repository, or API over
secondary summaries.

Record enough source identity, version, and observation time for another
operator to reproduce a material compatibility or delivery decision. Separate
verified facts from inference. If authoritative evidence is unavailable, state
the uncertainty and avoid converting it into a version floor, compatibility
claim, or irreversible action.

Never copy credentials, private payloads, or local-only paths into public
evidence. Cite only the minimum information needed to support the claim.
