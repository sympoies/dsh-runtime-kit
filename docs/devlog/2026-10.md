# Development log - 2026-10

## 2026-10-01 - Retired the plan-issue skills and adopted named work modes

### Result

- DSH sessions now receive the named work modes (`direct`, `issue`,
  `program`, `program/dispatch`) as a packaged delivery-phase policy,
  `agent-docs/WORK_MODES.md`, through
  `runtime_context({ intent: "project-dev", phase: "delivery" })`. The home
  instructions route to it before any issue, tracker, or delivery record.
- `runtime_context` gained an optional `phase` (`edit` by default, or
  `delivery`). The automatic mutation prerequisite still prepares only the
  edit phase, so the injected context stays the compact edit contract.
- Activation now stages every packaged `agent-docs/` policy document. Their
  name-to-digest map joins the asset-set digest as `policy_documents_sha256`
  only when a package ships one, so earlier targets keep their accepted digest
  and rollback to them still verifies.
- Removed `deliver-plan-tracking-issue`, rewrote `deliver-dispatch-plan` on a
  tracker plus lane child issues through `forge-cli`, and added program mode,
  its tracker template, and the tracker row grammar to `issue-follow-up`. No
  bundled skill references `plan-issue`, `plan-tooling`, or the numbered tier
  codes any more, and the manifest no longer declares those commands.

### Why / context

- The validated nils-cli release no longer ships `plan-issue` or
  `plan-tooling`, so two bundled skills called missing commands. The
  agent-runtime kit had already replaced the tier ladder with named modes and
  retired the plan workflow; this ports that change in DSH-native form.
- A delivery-phase policy cannot join the edit phase: the prerequisite injects
  every required edit document before the first mutation within a 20 KiB
  budget. An explicit phase keeps larger delivery policy on demand, which the
  packaged home policies of the same program will reuse.

### Evidence

- Regressions failed first: packaged skills still named the retired workflow,
  `runtime_context` had no `phase`, and the packaged catalog declared no
  work-modes document.
- New operations tests stage two policy documents, roll back to a package
  without them, and reject a replaced or planted document and an undeclared
  `agent-docs` entry.
- The repository catalog smoke resolves `WORK_MODES.md` for DSH in the
  `delivery` phase with the released `agent-docs`.
