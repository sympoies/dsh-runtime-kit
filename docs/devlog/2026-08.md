## 2026-08-25 - Replace Darwin directory projection with transient verified execution

**Result**

- Authenticated companion snapshots now retain read-only executable file
  handles plus private mode-`0500` self-resolution links beneath a mode-`0700`
  random root until every child scope settles. Runtime commands and all
  long-lived nils transports execute only through the retained file
  descriptions; inode-bound disposal preserves foreign replacements and warns
  about a relocated private root rather than deleting uncertain names.
- The version-scoped DSH patch now adds a fail-closed
  `SubprocessRuntime.spawnDescriptor` primitive. The local provider maps the
  caller-owned executable to child fd 3 and launches `/proc/self/fd/3` on
  Linux. On Darwin it copies exact descriptor bytes into a private mode-`0500`
  file beneath a fresh mode-`0700` directory, verifies source stability and
  target SHA-256, requires every temp-parent ancestor to be owned by root or
  the current UID, rejects an untrusted writable chain, revalidates both
  private identities immediately before spawn, and retains that path until
  synchronous spawn failure or complete process-tree settlement so descendant
  executable self-inspection remains valid. The requested `argv[0]` remains
  display identity only.
- Linux and macOS compatibility lanes run the native subprocess regression in
  addition to the tools and LLM boundary suites. Providers without descriptor
  execution cannot silently fall back to an ordinary path.

**Why / context**

- The preceding repair assumed Darwin could reopen a directory through
  `/dev/fd/<fd>` and traverse a child entry. The macOS provider lane disproved
  that assumption with `ENOTDIR`; Darwin's file-descriptor namespace is not a
  directory-projection equivalent of Linux procfs.
- DSH's public subprocess spec exposes only argv, cwd, environment, and the
  three standard streams. It cannot inherit an authenticated executable FD,
  so this missing native boundary belongs in the same hash-authenticated
  downstream patch as the tool and model admission seams.
- The first descriptor-execution provider run reached patched DSH typechecking
  and exposed that the local provider method also needed TypeScript's explicit
  `override` modifier. All affected Linux release rows reported the same
  `noImplicitOverride` failure, making this a patch contract defect rather than
  a platform execution failure.
- The replacement macOS run then reached the runtime-provider suite. Eleven of
  thirteen tests passed; the two project-audit fixtures returned `/var` paths
  after production had correctly canonicalized them to `/private/var`. The
  fixture now canonicalizes its temporary root instead of weakening strict
  production path matching.
- The following macOS run passed the provider suite and reached all three DSH
  native suites. Direct `spawn("/dev/fd/3")` then failed with `EACCES`, proving
  that Darwin fdesc entries are readable projections but not executable
  pathnames. A subsequent attempt to start `/usr/lib/dyld` as an executable
  bridge failed with `ENOEXEC`; dyld is not a supported descriptor-exec shim.
  The provider therefore keeps the descriptor as byte authority through
  per-spawn verified materialization. macOS still has no atomic fd-to-exec
  transition, so a malicious same-UID race remains an explicit platform risk.
- A packed-runtime RED proved that eager unlink breaks nils-cli self-inspection:
  `current_exe()` could not canonicalize the deleted executable and the
  finish-line runner exited 69. Private links are therefore retained as
  non-authoritative self-resolution aids. Replacing or relocating their root
  still cannot redirect Linux execution, and inode-bound disposal does not
  remove a foreign replacement.
- A later packed-runtime RED proved that Cordis intentionally returns a fresh
  trace wrapper for a service method on each access. Binding wrapper identity
  therefore rejected the unchanged real subprocess provider. Runtime-kit now
  authenticates Cordis' public original service identity, declared mode, and
  raw method while still invoking through the traced receiver; an in-place
  provider method replacement remains fail-closed.
- The first exact-head required-check run exposed two portability defects that
  local Linux had not represented. The CI Node executable exceeded the patch's
  original 64 MiB descriptor ceiling, and macOS canonicalized `/var` fixture
  paths to `/private/var` while a global one-shot unlink failure could be
  consumed by unrelated cleanup. The bounded executable ceiling is now 256
  MiB, the ownership fixture uses its canonical path, and cleanup injection is
  bound to the exact materialized executable. A separate Node 22 failure showed
  that a policy-timeout test released its child after a wall-clock sleep; it
  now waits for the actual abort event before releasing the process tree.

**Evidence**

## 2026-08-25 - Move runtime health admission out of model prompts

**Result**

- The issue #58 candidate adds a native `RuntimeHealth` Cordis service with
  frozen typed snapshots, scoped probes, recovery, provider retirement, and
  model-hidden admission. Project health is refreshed by DSH's pre-waterfall
  model guard; capability-dependent tools are fenced by the native tool guard.
- Companion authentication now retains immutable executable snapshots across
  every long-lived nils transport. Scoped descriptor leases drain executable
  resolution, spawn, response validation, process-tree quiescence, cleanup,
  and HMR disposal before the snapshot can close or be reused.
- The downstream DSH patch is authenticated by release revision, patch digest,
  and before/after hashes. It extends only the native tools and LLM public

  lease covering only the final spawn call.

  version-scoped patch is maintained out of tree in this repository; no DSH
  fork, vendored source, or upstream contribution is introduced.
