# Development log - 2026-08

## 2026-08-21 - Product and contributor documentation separated

**Result**

- The root README was reduced from 799 to 115 lines and now serves DSH users
  with the product purpose, supported runtime, activation path, capabilities,
  and documentation map.
- Routine contributor setup and validation moved to `DEVELOPMENT.md`; focused
  operations, compatibility, and acceptance guides plus a docs index now own
  the corresponding long-form material.
- Architecture gained navigable section headings, and coexistence contract
  coverage now checks the canonical operations guide instead of requiring
  internal activation detail in the user-facing README.

**Why / context**

- The README had accumulated runtime internals, contributor commands,
  operations procedures, promotion evidence, and compatibility detail. That
  made the package difficult for a non-contributor to evaluate and try.
- Separating documents by audience follows the repository convention that
  everyday development and test guidance belongs in `DEVELOPMENT.md`, while
  agent-docs remains a compact DSH runtime context asset rather than a human
  documentation store.

**Evidence**

- `npm test` passed 291/291 tests and `npm run typecheck` passed.
- `npm run benchmark:policy` passed 2,000 samples with p95 0.133 ms and no
  active operations or live handles after teardown.
- A local Markdown scan resolved links across 90 files, `git diff --check`
  passed, and `npm pack --dry-run --json` included every new documentation
  entrypoint.

## 2026-08-21 - Native DSH runtime migration completed

**Result**

- The public out-of-tree runtime kit reached `main` through PR #26, with the
  final parity evidence and migration state repair following in PR #27.
- DSH now uses dsh-runtime-kit plus nils-cli while Codex and Claude Code retain
  agent-runtime-kit plus nils-cli; the profiles coexist without cross-loading.

**Why / context**

- The terminal architecture is additive, not a provider replacement. DSH owns
  its native agent, tool, session, sandbox, skill, and subagent surfaces while
  nils-cli remains the shared deterministic policy and workflow boundary.
- Keeping the two runtime layers isolated makes DSH activation reversible and
  avoids coupling this package to the existing provider runtime.

**Evidence**

- Hosted acceptance run `32447387497` completed 12 scenarios with 12 passed,
  0 pending, and 0 failed against released nils-cli v1.27.0 and DSH rc.7.
- Compatibility run `32447803170` completed four green jobs before PR #26
  merged. A local profile check reported DSH doctor healthy and the real
  `runtime_kit_plus_one` tool returned `42` for `41`.

## 2026-08-20 - Acceptance became hermetic and profile-safe

**Result**

- The acceptance path preserved the hosted tool runtime, reused only an
  authenticated pnpm store and DSH lockfile, tolerated executable-mode
  normalization, and installed into native or clean DSH profiles offline.
- Operations recovery was hardened around canonical profile roots, atomic
  collateral restoration and removal, bounded activation assets, and exact
  ownership adoption.

**Why / context**

- A green source-level test was insufficient for the final coexistence claim.
  Acceptance needed to prove that a packed candidate could run without network
  resolution, mutate neither the upstream checkout nor unrelated provider
  state, and recover safely across interrupted profile operations.

**Evidence**

- The final local package suite reached 254/254 tests with typechecking, both
  compatibility benchmarks, package inspection, and packed rc.7 smoke green.
- The hosted-rehearsal sequence progressed from authorization-pending runs to
  the terminal credentialless 12/12 acceptance recorded in the migration
  state, while the upstream DSH checkout remained clean.

## 2026-08-19 - Native policy, review, and lane orchestration integrated
