## 2026-08-25 - Bind automatic prerequisites at the native DSH execution boundary

**Result**

- The issue #57 candidate adds an exact-definition prerequisite seam to the
  DSH tools pipeline and implements automatic project-development context on
  that seam. Admission begins before any execution wrapper or tool body, while
  idempotent cache completion runs only after DSH has finalized and linearized
  the successful result.
- One version-scoped downstream patch is authenticated by revision, patch
  digest, and before/after source hashes. Runtime-kit owns idempotent
  check/apply/reverse commands; it does not fork, vendor, or propose the patch
  upstream.
- The runtime compatibility floor now uses the released nils-cli v1.27.8
  binaries required by the execution-prerequisite protocol.

**Why / context**

- Public registry and event wrappers cannot prove that the definition admitted
  before execution is the exact definition dispatched after HMR or a
  `tools/execute` short circuit. They also cannot place durable prerequisite
  context after the entire native post waterfall without duplicating DSH's
  dispatcher.
- The native seam keeps caller cancellation, tamper-evident agent and call
  identity, HMR replacement checks, result finalization, and completion
  linearization inside the owner of tool execution. Runtime-kit supplies policy
  behavior and bounded idempotent cache reconciliation; agents do not
  reconstruct this evidence or retry shell commands themselves.

**Evidence**

  substitution, identity mutate-and-restore, successful execute short
  circuits, late cancellation, one-shot scheduler replay, prerequisite binding

  0.1.0-rc.8, and 0.1.1-rc.2 with automatic and Code Mode nested

## 2026-08-24 - Enforce workspace ownership through native DSH lifecycle

**Result**

- The shipped bundle now activates WorkspaceLease before policy and registers
  a strict nils-cli provider for bind, begin, complete, renew, and release.
  DSH supplies authenticated Agent, Session, tool, cancellation, and disposal
  facts; nils-cli remains the sole owner of Git identity, durable exclusion,
  operation fencing, and recovery policy.
- A live child with an exact immutable parent lineage and the same checkout may
  share its ancestor's provider binding with a distinct process-local opaque
  reference. Independent sessions still contend, while linked worktrees remain
  separate mutation domains.
- Explicit same-session `resume` and `compact` can recover released or expired
  dirty work only after every operation is terminal. Startup, clear, foreign

  commit time. Moving admission into the existing public DSH lifecycle makes
  the safety rule automatic without modifying, vendoring, or forking DSH and
  without duplicating Git policy in JavaScript.
- Recovery must preserve interrupted user work without turning a known session
  identifier into transferable authority. The host-authenticated session and
  parent digests therefore gate recovery, and every successful recovery mints
  a new binding and generation.

**Evidence**

  parity check, and the complete packed rc.7 acceptance smoke.

## 2026-08-24 - Validate the latest DSH and close finish-line turns durably

**Result**

- The compatibility matrix now authenticates DSH 0.1.1-rc.2 at its exact
  upstream revision and Agent Console TUI 0.9.0 while retaining the reviewed
  rc.7 and rc.8 compatibility rows.
- A successful finish-line stop now releases its exact turn capability before
  the agent becomes idle. Teardown drain preserves an already authenticated
  release for one bounded teardown grace while continuing to cancel ordinary
  in-flight requests.

**Why / context**

- DSH 0.1.1-rc.2 makes agent disposal explicit and does not await asynchronous
  disposal listeners. Depending on process teardown for the durable release

  and make a later resume fail closed.

  turn identity and capability, so release belongs there; disposal remains the
