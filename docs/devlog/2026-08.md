# Development log - 2026-08

## 2026-08-23 - Resolve portable nils commands before managed spawn

**Result**

- Policy, selective context, and finish-line transports now resolve portable
  `agent-hook` and `agent-docs` names through the DSH subprocess service before
  passing an absolute executable to managed spawn.
- Explicit absolute executable configuration remains unchanged, and every
  existing fail-closed timeout, output, exit, and process-tree check remains in
  force.

**Why / context**

- The runtime passed a bare executable name directly to a subprocess API whose
  spawn contract requires a fully resolved `argv[0]`. A live rc.7 turn could
  therefore load the plugin but fail policy admission, selective context, and
  finish-line completion before the nils child executed.
- Using the subprocess service's resolver keeps executable lookup aligned with
  its scrubbed child environment instead of duplicating host PATH logic in the
  runtime kit.

**Evidence**

- The regression first failed as `runtime-context-unavailable` when a fake
  subprocess rejected an unresolved command, then passed after resolution.
- The focused context, policy, and finish-line matrix passed 74/74, including
  bare-name coverage for all three transports and a pre-spawn deadline check.

## 2026-08-23 - Empty profiles accept an owned generated lock

**Result**

- Setup now accepts pnpm creating a new lockfile only when its sole importer,
  package, and empty snapshot root bind the reviewed runtime-kit artifact and
  removing that root leaves the exact default lock structure.
- Any unrelated importer, dependency, setting, package, snapshot, or metadata
  still counts as collateral and is restored and rejected.

**Why / context**

- DSH rc.8 creates `pnpm-lock.yaml` during the first plugin installation even
  when the profile previously had no lockfile. The operations projection
  treated every absent-to-present lock transition as unrelated mutation, so a
  valid first Workbench activation rolled back.
- The exception is deliberately structural rather than version-wide: package
  and activation digests remain authoritative, runtime-kit-prefixed keys are
  not ownership evidence, and only an otherwise empty pnpm 9 lock is
  equivalent to the absent pre-install state.

**Evidence**

- The regression first failed with `native-dsh-collateral-mutation`, matching
  the live rc.8 profile, then passed together with the existing unrelated-lock
  rejection case.
- The final focused generated-lock matrix passed 9/9; the complete affected
  operations suite passed 81/81 and strict typechecking
  passed.

## 2026-08-22 - POSIX command containment became host-tool independent

**Result**

- Governed operations now create their isolated session and process group
  through Node's POSIX `detached` child-process contract instead of resolving
  a host-provided `setsid` executable.
- The supervisor reports its command pgid over the private control descriptor,
  so timeout, output-limit, supervisor-loss, and descendant cleanup retain the
  same fail-closed quiescence proof on Linux and macOS.

**Why / context**

- macOS provides POSIX process groups but does not ship the Linux `setsid`
  command. Treating that executable as a prerequisite prevented an otherwise
  compatible DSH profile from reaching even a setup preview.
- Keeping process-group creation inside the existing Node supervisor removes a
  host package dependency without weakening the negative-pgid cleanup boundary.

**Evidence**

- The new no-`setsid` regression failed with typed `command-unavailable` before
  the fix and passed afterward.
- Focused timeout, live-descendant, supervisor-loss, and owner-repair scenarios
  passed, along with strict typechecking.
- A real macOS Node 26 / DSH rc.7 setup preview completed with `ok: true` while
  the host provided no external `setsid` executable.
